Tes ateliers : un skill, huit ateliers

Le fil rouge de la formation, au même endroit. Une vraie PR Angular 22, écrite trop vite, avec {{R:opus:0:attendus}} problèmes cachés et 7 leurres. Tu construis ton skill de review en six versions (v0 à v5), du premier jet à la version partagée, puis tu l'automatises dans le module 3 (ateliers 6 et 7). À chaque atelier, tu le lances, tu le notes, tu suis ton score. Bloqué ? Chaque atelier a son rattrapage.

⏱ {{DUREE:m1+m2+m3}} leçons et ateliers, modules 1 à 38 ateliers · 2 bonusdépôt : skill-issue-playground

Avant de commencer

$ git clone https://github.com/PrincyExaltIT/skill-issue-playground.git
$ git clone https://github.com/PrincyExaltIT/skill-issue.git
$ cd skill-issue-playground
$ git checkout depart                 # la base de la PR, en local
$ git checkout lab/speaker-spotlight
$ npm install

Node.js 24.15 ou plus, ou 22.22.3 ou plus (node --version) : la CLI Angular 22.2 refuse de démarrer en dessous. Sous Windows, si git clone répond « Filename too long » : git config --global core.longpaths true. Si le clone répond « not found », le dépôt n'est pas encore ouvert à ton compte : demande un accès en lecture à PrincyExaltIT. Le second dépôt contient le corrigé, le score et le skill de référence : garde-le à côté, jamais dans le dépôt relu. Ton skill vit dans .claude/skills/revue-angular/ (Claude Code, Continue) ou .agents/skills/revue-angular/ (les autres harnesses) ; il reste non suivi par git pendant que tu le construis.

Bloqué à l'atelier N ? node ../skill-issue/course/rattrapage.mjs N remplace ton skill par la version de référence de l'étape N (--harness codex pour .agents/skills/, --harness tous pour les deux dossiers). Ton ancien dossier est mis de côté dans .review/ancien-skill/.

Atelier 0 · Ton skill en dix lignes

Un SKILL.md avec un nom, une description et trois consignes. Lance-le, note-le : c'est ton point de départ. Leçon 1.9

> /revue-angular Relis cette branche avant que je la merge sur depart.
$ node ../skill-issue/evals/angular-review/score.mjs --report .review/REVIEW.md
Le skill se déclenche et le rapport est noté. Référence : {{R:opus:0:rappel}} % avec Opus, {{R:haiku:0:rappel}} % avec Haiku.

Rattrapage : node ../skill-issue/course/rattrapage.mjs 0 (--harness codex pour .agents/skills/)

Atelier 1 · La procédure

Des étapes numérotées, chacune avec son critère « Fini quand », et un gabarit de rapport dans assets/. Leçon 2.2

Le rapport est un fichier, chaque finding cite fichier:ligne. Référence : {{R:opus:1:rappel}} % / {{R:haiku:1:rappel}} %.

Rattrapage : node ../skill-issue/course/rattrapage.mjs 1 (--harness codex pour .agents/skills/)

Atelier 2 · Les règles de ton équipe

Un dossier references/, un fichier par domaine, et la table qui dit quand charger chacun. Leçon 2.3

Le rapport cite tes identifiants de règles. Référence : {{R:opus:2:rappel}} % / {{R:haiku:2:rappel}} %.

Rattrapage : node ../skill-issue/course/rattrapage.mjs 2 (--harness codex pour .agents/skills/)

Atelier 3 · Les scripts

perimetre.mjs et verifs.mjs, plus une règle mécanique à toi, écrite dans la table REGLES (exemple pas à pas dans la leçon 2.4).

$ cp -r ../skill-issue/course/revue-angular/etape-3/revue-angular/scripts .claude/skills/revue-angular/   # ou .agents/skills/revue-angular/
$ node .claude/skills/revue-angular/scripts/perimetre.mjs --base depart
$ node .claude/skills/revue-angular/scripts/verifs.mjs
Tes pistes sortent en moins d'une seconde, sans modèle, y compris celle de ta règle, et chacune finit confirmée ou écartée. Référence : {{R:opus:3:rappel}} % / {{R:haiku:3:rappel}} %.

Rattrapage : node ../skill-issue/course/rattrapage.mjs 3 (--harness codex pour .agents/skills/)

Atelier 4 · Savoir dire non

assets/exemples.md avec tes pièges, et une étape de vérification qui réfute chaque finding. Leçon 2.5

Tes faux positifs passent dans « Écartés à la vérification », avec leur raison. Référence : {{R:opus:4:rappel}} % / {{R:haiku:4:rappel}} %.

Rattrapage : node ../skill-issue/course/rattrapage.mjs 4 (--harness codex pour .agents/skills/)

Atelier 5 · Le tester et le partager

Dix demandes qui doivent déclencher le skill et dix qui ne doivent pas (mesure automatique sous Claude Code, protocole à la main ailleurs), le validateur, les métadonnées, puis une PR qui commite le skill dans .agents/skills/ et .claude/skills/. Leçons 2.6 et 2.7

$ node ../skill-issue/skills/skill-smith/scripts/validate.mjs --strict .claude/skills/revue-angular
Au moins 9 réponses justes sur 10 dans chaque liste de déclenchement, 0 erreur au validateur. Puis un collègue, ou ton second clone dans un autre harness, lance ta review sans rien installer d'autre que le dépôt. Version de référence : branche equipe/main, à ouvrir à côté avec git worktree add ../equipe origin/equipe/main.

Rattrapage : node ../skill-issue/course/rattrapage.mjs 5 --harness tous (les deux dossiers ; --harness codex pour .agents/skills/ seul)

Atelier 6 · Ta chaîne

Deux skills de plus, à toi : corrige-review corrige les findings de .review/REVIEW.md, un commit par finding, tests après chacun ; raconte-branche écrit .review/PR.md à partir des commits et du rapport. Leçon 3.3

$ git switch -c ma-chaine lab/speaker-spotlight
> /revue-angular Relis cette branche avant que je la merge sur depart.
> /corrige-review
> /raconte-branche Décris cette branche pour sa PR vers depart.
Un commit par finding corrigé, avec sa règle dans le message ; les tests verts après chacun, ou un arrêt expliqué ; et un .review/PR.md qui donne un état à chaque finding.

Rattrapage : node ../skill-issue/course/rattrapage.mjs chaine (--harness codex pour .agents/skills/)

Atelier 7 · Le garde-fou automatique

Un hook Claude Code qui lance verifs.mjs après chaque édition de l'agent. Leçon 3.5

L'agent corrige de lui-même après le message du hook.

Rattrapage : node ../skill-issue/course/rattrapage.mjs 5 remet les scripts que le hook appelle (--harness codex pour .agents/skills/) ; le bloc du hook est dans la leçon 3.5.

Les deux bonus

Bonus cloud · ta PR relue en CI

Le workflow du kit dans ton fork : la porte sans IA se ferme sur les BLOCKER et annote le diff ; avec ta clé, le rapport arrive en commentaire. Démo : la PR #4. Leçon C.2

Rattrapage : la branche equipe/speaker-spotlight du dépôt de démo porte déjà le skill et le workflow.

Bonus package · compare avec celui de Princy

Installe le package sur une copie du dépôt, lance /angular-review sur la même PR, et compare ton rapport au sien : ce qu'il trouve en plus, ce que tu trouves qu'il rate. Leçon P.2

Rattrapage : l'installation tient en une commande, install.mjs --target, donnée dans la leçon P.1.

Pour aller plus loin : prends une vieille PR de ton propre projet, écris son corrigé au format de evals/angular-review/playground-key.json, et mesure ton skill sur ton code.
