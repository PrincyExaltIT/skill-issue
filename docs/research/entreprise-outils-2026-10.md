# Outils de code IA en entreprise : faits sourcés pour le module « Chez le client »

## Méthode

Collecte du 10 octobre 2026 : recherche web, puis lecture (WebFetch) des pages officielles de chaque éditeur. Environ 120 faits. Statuts : **VERIFIED** = lu le 10/10/2026 sur une page officielle ; **PRESS** = presse ou source secondaire seulement ; **UNVERIFIED** = non trouvé, contradictoire ou page non lisible (404, 403, contenu tronqué). Les redirections des docs ont été suivies (developers.openai.com vers learn.chatgpt.com ; developers.google.com vers docs.cloud.google.com). Les résumés ont été produits par un modèle léger à partir du texte lu : reprendre les noms de réglages et les citations exactes depuis la page avant diffusion en formation. Tarifs, plans et dates changent vite : à re-dater avant chaque session. Les outils cités sont des exemples, pas une liste fermée (« et bien d'autres »). Ce document ne donne ni conseil juridique ni conseil commercial.

## 1. GitHub Copilot (Business et Enterprise)

- **a1** — Plans : Copilot Business à 19 USD par siège et par mois ; Copilot Enterprise à 39 USD par siège et par mois (tarifs lus le 10/10/2026). Source : https://docs.github.com/en/copilot/get-started/plans — **VERIFIED**
- **a2** — Copilot Enterprise est conçu pour GitHub Enterprise Cloud ; la page précise que Copilot n'est pas disponible actuellement pour GitHub Enterprise Server. Source : https://docs.github.com/en/copilot/get-started/plans — **VERIFIED**
- **a3** — Politiques : réglées d'abord au niveau entreprise ; pour la plupart, l'entreprise active, désactive, ou laisse « Let organizations decide » (les organisations ne décident que si l'entreprise le permet). Source : https://docs.github.com/en/copilot/concepts/policies — **VERIFIED**
- **a4** — Politiques nommées sur la page d'administration : « Suggestions matching public code » (autorisée par défaut pour Copilot Business), « Copilot in GitHub.com », « MCP servers in Copilot » (qui ne contrôle pas les hôtes tiers comme Cursor, Windsurf ou Claude). Source : https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/manage-enterprise-policies — **VERIFIED**
- **a5** — Autres politiques citées : « Copilot cloud agent » (choix des organisations ou blocage global), « Copilot CLI » (distincte du client), « Models policy » (décrite comme active), et une politique de disponibilité par défaut pour les fonctionnalités GA. Source : https://docs.github.com/en/copilot/concepts/policies — **VERIFIED**
- **a6** — Politique « Restrict Copilot to data residency compliant models » (section Features), désactivée par défaut ; activée, elle envoie les requêtes d'inférence vers des endpoints de la région désignée. Source : https://docs.github.com/en/enterprise-cloud@latest/admin/data-residency/github-copilot-with-data-residency — **VERIFIED**
- **a7** — Residency Copilot : seulement les États-Unis et l'Union européenne ; GitHub annonce d'autres régions, sans calendrier. Source : https://docs.github.com/en/enterprise-cloud@latest/admin/data-residency/github-copilot-with-data-residency — **VERIFIED**
- **a8** — Activer la residency ajoute 10 % de consommation de crédits IA sur les requêtes conformes ; les fonctionnalités en preview ne sont couvertes qu'après GA. Source : https://docs.github.com/en/enterprise-cloud@latest/admin/data-residency/github-copilot-with-data-residency — **VERIFIED**
- **a9** — Le plan Copilot requis pour la residency n'est pas nommé sur la page (prérequis cités : GHE.com avec data residency, clients publiés en 2025 ou après). Source : https://docs.github.com/en/enterprise-cloud@latest/admin/data-residency/github-copilot-with-data-residency — **UNVERIFIED**
- **a10** — Changelog du 26 août 2026 : politique par défaut pour les modèles GA sur Copilot Business et Enterprise ; déploiement jusqu'au 1er septembre 2026 ; les modèles non configurés héritent de la politique globale (activée par défaut) ; les choix explicites sont conservés. Source : https://github.blog/changelog/2026-08-26-global-model-policy-generally-available — **VERIFIED**
- **a11** — Modèles « open-weight » (la page cite DeepSeek et Kimi K2) et modèles nécessitant une rétention de données : désactivés par défaut quelle que soit la politique ; l'admin doit les activer explicitement. Source : https://github.blog/changelog/2026-08-26-global-model-policy-generally-available — **VERIFIED**
- **a12** — Content exclusion : disponible pour Copilot Business et Enterprise ; configurable par les repository admins, les organization owners et les enterprise owners. Source : https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/content-exclusion — **VERIFIED**
- **a13** — Dans les fichiers exclus : pas de suggestions inline ; leur contenu n'alimente ni les suggestions d'autres fichiers ni les réponses du Chat ; la code review sur GitHub.com ignore ces fichiers. Source : https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/content-exclusion — **VERIFIED**
- **a14** — Limites : content exclusion non supportée dans les modes Edit et Agent de Copilot Chat sous VS Code et autres éditeurs ; des informations sémantiques (types, survol, configuration de build) peuvent atteindre le modèle indirectement via l'IDE. Source : https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/content-exclusion — **VERIFIED**
- **a15** — Content exclusion est en public preview sur le site GitHub et GitHub Mobile (« subject to change »). Source : https://docs.github.com/en/copilot/concepts/security-governance-and-network-settings/content-exclusion — **VERIFIED**

Source : https://docs.github.com/en/copilot/how-tos/configure-custom-instructions/add-organization-instructions — **VERIFIED**

## 2. Claude Code pour organisations

- **b1** — Offres pour organisations : Claude for Teams / Enterprise, Claude Console (API), Amazon Bedrock, Google Cloud's Agent Platform (ex-Vertex AI), Microsoft Foundry. Sans siège Teams ou Enterprise, les sessions cloud, Routines, Code Review, Remote Control et l'extension Chrome ne sont pas disponibles avec une clé Console ou des identifiants cloud seuls. Source : https://code.claude.com/docs/en/admin-setup — **VERIFIED**
- **b2** — La livraison des réglages managés par la console claude.ai demande un plan Teams ou Enterprise ; les réglages serveur sont lus au démarrage et rafraîchis toutes les heures. Source : https://code.claude.com/docs/en/admin-setup — **VERIFIED**
- **b3** — Offres commerciales (Team, Enterprise, API, fournisseurs tiers) : Anthropic n'entraîne pas ses modèles sur le code ni les prompts envoyés à Claude Code, sauf opt-in explicite (ex. Development Partner Program, réservé à l'API first-party). Source : https://code.claude.com/docs/en/data-usage — **VERIFIED**
- **b4** — Rétention standard des données Claude Code pour Team, Enterprise et API : 30 jours. Source : https://code.claude.com/docs/en/data-usage — **VERIFIED**
- **b5** — Zero Data Retention : disponible pour des comptes qualifiés sur Claude for Enterprise, activée par organisation par l'account team ; non incluse dans l'Enterprise standard. Source : https://code.claude.com/docs/en/data-usage — **VERIFIED**
- **b6** — Transcripts locaux : stockés en clair sous `~/.claude/projects/` pendant 30 jours par défaut ; réglage `cleanupPeriodDays`. Source : https://code.claude.com/docs/en/data-usage — **VERIFIED**
- **b7** — `/feedback`, `/bug` et `/share` envoient l'historique (code inclus) à Anthropic, conservé 5 ans ; désactivable avec `DISABLE_FEEDBACK_COMMAND=1`. Source : https://code.claude.com/docs/en/data-usage — **VERIFIED**
- **b8** — Télémétrie : `DISABLE_TELEMETRY=1` (métriques), `DISABLE_ERROR_REPORTING=1` (erreurs), `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` (tout le non essentiel) ; sondages : `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1`. Source : https://code.claude.com/docs/en/data-usage — **VERIFIED**
- **b9** — Sur Bedrock, Agent Platform et Foundry, métriques, erreurs et /feedback sont désactivés par défaut ; les sondages et la vérification WebFetch restent actifs. Source : https://code.claude.com/docs/en/data-usage — **VERIFIED**
- **b10** — WebFetch envoie le nom d'hôte (jamais l'URL complète) à api.anthropic.com pour un contrôle de sécurité ; `skipWebFetchPreflight: true` le désactive ; si ce domaine est bloqué, WebFetch échoue. Source : https://code.claude.com/docs/en/data-usage — **VERIFIED**
- **b11** — Les managed settings priment sur les réglages user, projet, local et `--settings` ; quelques exceptions de sécurité laissent passer une valeur plus stricte d'un niveau inférieur. Source : https://code.claude.com/docs/en/managed-settings — **VERIFIED**
- **b12** — Chemins des fichiers managés : macOS `/Library/Application Support/ClaudeCode/managed-settings.json` ; Linux et WSL `/etc/claude-code/managed-settings.json` ; Windows `C:\Program Files\ClaudeCode\managed-settings.json`. Le chemin `C:\ProgramData\ClaudeCode\` n'est plus lu. Source : https://code.claude.com/docs/en/managed-settings — **VERIFIED**
- **b13** — Autres canaux : Windows `HKLM\SOFTWARE\Policies\ClaudeCode`, valeur `Settings` contenant du JSON ; macOS, domaine `com.anthropic.claudecode` (profil MDM) ; `HKCU` existe mais a la priorité la plus faible et s'écrit sans élévation. Source : https://code.claude.com/docs/en/managed-settings — **VERIFIED**
- **b14** — Vérification : dans `/status`, la ligne « Setting sources » doit afficher « Enterprise managed settings » suivi de la source entre parenthèses, par exemple `(file)`. Source : https://code.claude.com/docs/en/managed-settings — **VERIFIED**
- **b15** — Clés de verrouillage : `permissions.disableBypassPermissionsMode`, `permissions.disableAutoMode` (valeur `"disable"`), `allowManagedPermissionRulesOnly`, `allowManagedHooksOnly`, `allowManagedMcpServersOnly`, `strictKnownMarketplaces`, `forceLoginMethod`, `forceLoginOrgUUID`, `availableModels` avec `enforceAvailableModels`. Source : https://code.claude.com/docs/en/admin-setup — **VERIFIED**
- **b16** — Les listes (`permissions.allow`, `permissions.deny`, `sandbox.network.allowedDomains`, `deniedMcpServers`) se cumulent entre sources : un développeur peut ajouter des entrées, pas en retirer. Source : https://code.claude.com/docs/en/admin-setup — **VERIFIED**
- **b17** — Modes de permission : `default`, `acceptEdits`, `plan`, `auto`, `dontAsk` (tout ce qui demanderait confirmation est refusé), `bypassPermissions` (réservé aux conteneurs ou VM isolés). Source : https://code.claude.com/docs/en/permission-modes — **VERIFIED**
- **b18** — Mode `auto` : un classifieur remplace l'humain sur les actions ; mode de départ par défaut à partir de la v2.1.283 pour le terminal interactif et VS Code (avant : Pro, Max et Team seulement) ; désactivable par `permissions.disableAutoMode`. Source : https://code.claude.com/docs/en/permission-modes — **VERIFIED**
- **b19** — Sandbox : macOS (Seatbelt), Linux et WSL2 (bubblewrap et socat). Sur Windows natif, Claude Code exécute les commandes sans sandbox : il faut WSL2 pour en bénéficier. Désactivé par défaut (`sandbox.enabled`, commande `/sandbox`). Source : https://code.claude.com/docs/en/sandboxing — **VERIFIED**
- **b20** — Le sandbox ne couvre que les commandes shell (Bash, PowerShell, Monitor) et leurs processus ; les outils Read, Edit, Write, WebFetch, les serveurs MCP et les hooks restent hors sandbox. Source : https://code.claude.com/docs/en/sandboxing — **VERIFIED**
- **b21** — Réseau du sandbox : filtrage par liste de domaines (`sandbox.network.allowedDomains`, vide au départ) ; `sandbox.network.allowManagedDomainsOnly` ne retient que les domaines managés. Source : https://code.claude.com/docs/en/managed-settings — **VERIFIED**
- **b22** — Installation native sous Windows sans droits administrateur ; Git for Windows est recommandé (Git Bash) mais facultatif ; sans lui, l'outil PowerShell sert de shell. Source : https://code.claude.com/docs/en/setup — **VERIFIED**
- **b23** — Méthodes d'installation : script natif (`irm https://claude.ai/install.ps1 | iex`), WinGet (`Anthropic.ClaudeCode`, sans auto-update), npm (`@anthropic-ai/claude-code`, Node.js 22 ou plus, « Do NOT use sudo »), Homebrew, apt, dnf, apk. Source : https://code.claude.com/docs/en/setup — **VERIFIED**
- **b24** — Mise à jour automatique en arrière-plan pour l'installation native ; `DISABLE_AUTOUPDATER` coupe la vérification de fond ; `DISABLE_UPDATES` bloque aussi les mises à jour manuelles. Source : https://code.claude.com/docs/en/setup — **VERIFIED**
- **b25** — Sur un home en stockage réseau partagé, un binaire supprimé pendant une session fait planter celle-ci (« Bus error » sous Linux) ; la doc recommande `DISABLE_UPDATES` et une installation locale par machine. Source : https://code.claude.com/docs/en/setup — **VERIFIED**
- **b26** — Chaque release publie un `manifest.json` signé GPG (empreinte `31DD DE24 DDFA B679 F42D 7BD2 BAA9 29FF 1A7E CACE`) ; le binaire Windows est signé « Anthropic, PBC ». Source : https://code.claude.com/docs/en/setup — **VERIFIED**
- **b27** — Bedrock : `CLAUDE_CODE_USE_BEDROCK=1`, `AWS_REGION`, épinglage par `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`, `ANTHROPIC_DEFAULT_HAIKU_MODEL` ; IAM : `bedrock:InvokeModel`, `bedrock:InvokeModelWithResponseStream`, `bedrock:ListInferenceProfiles`, `bedrock:GetInferenceProfile`. Source : https://code.claude.com/docs/en/amazon-bedrock — **VERIFIED**
- **b28** — Bedrock : WebSearch indisponible et `/logout` indisponible ; authentification via la chaîne AWS, un profil SSO, `AWS_BEARER_TOKEN_BEDROCK` ou `awsAuthRefresh`. Source : https://code.claude.com/docs/en/amazon-bedrock — **VERIFIED**
- **b29** — Agent Platform (ex-Vertex AI) : `CLAUDE_CODE_USE_VERTEX=1`, `CLOUD_ML_REGION`, `ANTHROPIC_VERTEX_PROJECT_ID`, rôle `roles/aiplatform.user`, `gcpAuthRefresh` pour renouveler les identifiants. Source : https://code.claude.com/docs/en/google-vertex-ai — **VERIFIED**
- **b30** — Foundry : `CLAUDE_CODE_USE_FOUNDRY=1` et `ANTHROPIC_FOUNDRY_RESOURCE` (nom seul, pas d'URL) ; authentification par clé API, Entra ID (`az login`) ou jeton bearer ; pas de vérification de modèle au démarrage. Source : https://code.claude.com/docs/en/microsoft-foundry — **VERIFIED**
- **b31** — Foundry « Hosted on Azure » : prompts et complétions restent dans Azure (seules des métadonnées d'usage et les contenus signalés par les systèmes de sécurité sortent) ; « Hosted on Anthropic » : requêtes routées vers l'infrastructure Anthropic. Source : https://code.claude.com/docs/en/data-usage — **VERIFIED**
- **b32** — Épinglage : sans pin, les alias `opus` et `sonnet` suivent le défaut de Claude Code et peuvent changer pour tous les utilisateurs ; Anthropic recommande d'épingler les versions pour un déploiement multi-utilisateurs. Source : https://code.claude.com/docs/en/amazon-bedrock — **VERIFIED**

- **c5** — Entraînement : la page d'administration ne précise pas si les données Business ou Enterprise servent à l'entraînement par défaut. Source : https://learn.chatgpt.com/docs/enterprise/admin-setup — **UNVERIFIED**
- **c6** — OpenAI annonce que les données ChatGPT Business sont exclues de l'entraînement par défaut (opt-in explicite pour y participer) ; la page openai.com/business-data a répondu 403 à la collecte. Source : https://openai.com/business-data/ — **UNVERIFIED**
- **c7** — Fichiers de configuration managée : `/etc/codex/requirements.toml` (Unix, dont Linux et macOS) ou `%ProgramData%\OpenAI\Codex\requirements.toml` (Windows) ; sur macOS, profil MDM `com.openai.codex:requirements_toml_base64`. Source : https://learn.chatgpt.com/docs/enterprise/managed-configuration.md — **VERIFIED**
- **c8** — Priorité des exigences, du plus fort au plus faible : MDM macOS, cloud (Agent Security), `managed_config.toml` hérité, `requirements.toml` système. Source : https://learn.chatgpt.com/docs/enterprise/managed-configuration.md — **VERIFIED**
- **c9** — Clés imposables (extrait) : `allowed_approval_policies`, `allowed_sandbox_modes`, `allowed_web_search_modes`, liste `[mcp_servers]` approuvée (liste vide = aucun MCP), `[features]`, `allow_managed_hooks_only`, `[rules]` (prefix_rules), `[permissions.filesystem]` avec `deny_read`. Source : https://learn.chatgpt.com/docs/enterprise/managed-configuration.md — **VERIFIED**
- **c10** — Les managed defaults (`managed_config.toml`) sont des valeurs de départ que l'utilisateur peut changer en session ; les exigences ne le sont pas : en cas de conflit, Codex bascule sur une valeur compatible et prévient l'utilisateur. Source : https://learn.chatgpt.com/docs/enterprise/managed-configuration.md — **VERIFIED**
- **c11** — Modes de sandbox : `read-only`, `workspace-write` (défaut en local), `danger-full-access` (sans frontière fichiers ni réseau) ; politiques d'approbation `on-request` et `never` ; `untrusted` n'est plus sélectionnable. Source : https://learn.chatgpt.com/docs/sandboxing.md — **VERIFIED**
- **c12** — Sandbox par OS : Seatbelt sur macOS, bubblewrap (`bwrap`) sur Linux et WSL2, sandbox natif Windows quand Codex tourne dans PowerShell. Source : https://learn.chatgpt.com/docs/sandboxing.md — **VERIFIED**
- **c13** — Le sandbox s'applique aux commandes lancées (git, gestionnaires de paquets, tests), pas seulement aux opérations fichiers intégrées. Source : https://learn.chatgpt.com/docs/sandboxing.md — **VERIFIED**

## 6. Réalités du réseau d'entreprise (proxy, CA, miroirs, droits)

- **f1** — npm : clés `registry`, `proxy`, `https-proxy`, `noproxy` (défaut : valeur de `NO_PROXY`), `cafile`, `strict-ssl` (vrai par défaut) ; équivalents en variables `NPM_CONFIG_*`. Source : https://docs.npmjs.com/cli/v10/using-npm/config — **VERIFIED**
- **f2** — npm : `cafile` pointe vers un fichier contenant une ou plusieurs autorités de certification ; `ca` est la version en ligne. Source : https://docs.npmjs.com/cli/v10/using-npm/config — **VERIFIED**
- **f3** — pip : option `--cert` avec la variable `PIP_CERT` ; la page cite aussi `REQUESTS_CA_BUNDLE` et `CURL_CA_BUNDLE`. Source : https://pip.pypa.io/en/stable/topics/https-certificates/ — **VERIFIED**
- **f4** — pip sous Windows : `%APPDATA%\pip\pip.ini` (utilisateur), `C:\ProgramData\pip\pip.ini` (global) ; `PIP_CONFIG_FILE` désigne un fichier chargé en dernier qui surcharge les autres. Source : https://pip.pypa.io/en/stable/topics/configuration/ — **VERIFIED**
- **f5** — Artifactory : créer un dépôt npm de type remote (Administration, Repositories, Create a Repository) pointant vers l'amont npm ; droits Admin ou Project Admin requis. Source : https://docs.jfrog.com/artifactory/docs/npm-repositories — **VERIFIED**
- **f6** — Artifactory : client npm pointé par `npm config set registry https://<artifactory>/artifactory/api/npm/<repo>/` ou par `.npmrc` (`registry=` et `_authToken`) ; JFrog recommande un dépôt virtuel comme registre par défaut. Source : https://docs.jfrog.com/artifactory/docs/npm-repositories — **VERIFIED**
- **f7** — Artifactory : la page ne dit pas si l'amont npmjs.org exige une authentification ; la presse parle d'un « Test Connection » avec jeton npmjs, à vérifier. Source : https://docs.jfrog.com/artifactory/docs/npm-repositories — **UNVERIFIED**
- **f8** — Nexus : proxy npm défini par un nom, une URL distante (ex. `https://registry.npmjs.org`) et un blob store ; un groupe peut agréger plusieurs proxies sous une seule URL. Source : https://help.sonatype.com/repomanager3/formats/npm-registry — **VERIFIED**
- **f9** — Nexus PyPI : URL distante `https://pypi.org/` et index exposant `/simple` requis (page PyPI Sonatype non lue). Source : https://help.sonatype.com/repomanager3/pypi-repositories — **UNVERIFIED**
- **f10** — Claude Code : `HTTPS_PROXY` recommandé (`HTTP_PROXY` en repli) ; `NO_PROXY` accepte une liste séparée par espaces ou virgules, ou `*` ; SOCKS non supporté ; le proxy est lu une fois, au démarrage. Source : https://code.claude.com/docs/en/network-config — **VERIFIED**
- **f11** — Claude Code : identifiants proxy dans l'URL déconseillés ; pour NTLM ou Kerberos, la doc suggère une passerelle LLM compatible ; mTLS via `CLAUDE_CODE_CLIENT_CERT`, `CLAUDE_CODE_CLIENT_KEY` (et passphrase optionnelle). Source : https://code.claude.com/docs/en/network-config — **VERIFIED**
- **f12** — Claude Code : CA d'entreprise via `NODE_EXTRA_CA_CERTS=/chemin/ca.pem` ; par défaut, le bundle Mozilla et le magasin OS sont approuvés (`CLAUDE_CODE_CERT_STORE`, défaut `bundled,system`) ; les proxys d'inspection TLS passent sans réglage si leur racine est dans le magasin OS et lue par le runtime (Node 22.15+ pour npm). Source : https://code.claude.com/docs/en/network-config — **VERIFIED**
- **f13** — Claude Code : domaines à ouvrir (liste officielle) : `api.anthropic.com`, `claude.ai`, `platform.claude.com`, `downloads.claude.ai`, `registry.npmjs.org` (installs npm et serveurs MCP lancés par `npx`), `github.com`, `code.claude.com` (docs). Source : https://code.claude.com/docs/en/network-config — **VERIFIED**
- **f14** — Installation native par utilisateur (`%USERPROFILE%\.local\bin\claude.exe`, `%USERPROFILE%\.local\share\claude`) : pas de droits admin ; les réglages managés, eux, s'écrivent avec des droits admin (HKLM, `C:\Program Files\`). Source : https://code.claude.com/docs/en/setup — **VERIFIED**
- **f15** — Lanceur d'entreprise : `CLAUDE_CODE_PROCESS_WRAPPER` (ou `processWrapper`) impose un lanceur à tous les processus Claude Code, mais la variable est ignorée sous Windows (les processus démarrent sans lanceur). Source : https://code.claude.com/docs/en/corporate-launcher — **VERIFIED**
- **f16** — Aucune page officielle lue (Claude Code, Copilot, Codex) ne traite précisément des environnements VDI ou bastion. Source : https://code.claude.com/docs/en/setup — **UNVERIFIED**

## Ce qu'un consultant doit vérifier avant d'installer

Chaque point renvoie aux faits ci-dessus. Un point qui dépend d'un fait UNVERIFIED ne se promet pas au client sans réponse écrite de l'éditeur.

1. **Le plan réellement payé par le client.** Copilot Business ou Enterprise (a1, a2) ; Claude for Teams / Enterprise ou fournisseur cloud (b1, b2) ; ChatGPT Enterprise pour Codex (c1) ; Privacy Mode imposé pour Cursor (d1).
2. **Qui contrôle quoi côté éditeur.** Politiques Copilot et « Let organizations decide » (a3, a4) ; politique globale des modèles (a10, a11) ; réglages managés verrouillés, puis vérifiés dans `/status` (b11, b14, b15).
3. **Les exclusions de fichiers Copilot.** Exclure les fichiers sensibles (a12, a13) ; ne pas supposer que les modes Edit et Agent de VS Code sont couverts (a14) ; fonction en preview sur GitHub.com (a15) ; nom exact du réglage à confirmer (a16).
4. **Rétention et entraînement, outil par outil.** Claude : pas d'entraînement en offre commerciale (b3), 30 jours (b4), ZDR à négocier à part (b5), /feedback conservé 5 ans à bloquer (b7). Copilot : entraînement connu seulement par la presse (a23), rétention non chiffrée (a24), changement annoncé non confirmé (a25). Codex : rétention sans chiffre et entraînement non confirmé (c3, c5, c6). Cursor : pas d'entraînement avec Privacy Mode (d2). Gemini : pas d'entraînement sur les prompts, mais code privé stocké en personnalisation (d7, d8, d9). Demander la réponse par écrit (DPA) pour tous les points UNVERIFIED.
5. **La résidence des données.** Copilot : US et UE seulement, politique à activer (a6, a7) ; Cursor : US pour Enterprise, UE d'inférence sur demande (d3) ; Codex : UE non citée (c4) ; Foundry : « Hosted on Azure » ou « Hosted on Anthropic » (b31) ; Mistral : hébergement UE contesté (d15).
6. **Les flux sortants.** Couper la télémétrie et les sondages (b8, b9) ; décider du sort de WebFetch (b10) ; sur Bedrock, WebSearch n'existe pas (b28) ; ouvrir la liste officielle de domaines et rien d'autre (f13).
7. **Le sandbox sur Windows.** Le sandbox Claude Code ne tourne pas en Windows natif : prévoir WSL2 (b19) ; le sandbox Codex existe en natif Windows via PowerShell (c12).
8. **Le lanceur d'entreprise.** Si le client impose un lanceur, `CLAUDE_CODE_PROCESS_WRAPPER` est ignoré sous Windows : compter ces postes comme non lancés (f15).
9. **Proxy, CA et TLS.** Si l'inspection TLS n'est pas dans le magasin OS, ajouter `NODE_EXTRA_CA_CERTS` (f12) ; npm : `proxy`, `noproxy`, `cafile` (f1, f2) ; pip : `PIP_CERT` (f3) ; Ollama : `HTTPS_PROXY` seul et certificat système (e4) ; Claude Code : `NO_PROXY` accepté, SOCKS refusé (f10).
10. **Miroirs de paquets.** Artifactory : dépôt npm remote puis dépôt virtuel comme registre (f5, f6) ; vérifier l'authentification vers npmjs.org (f7) ; Nexus : proxy npm vers `https://registry.npmjs.org`, éventuellement groupé (f8) ; PyPI à valider (f9).
11. **Droits et mises à jour.** L'installation native de Claude Code ne demande pas d'admin (f14, b22) ; les réglages managés, eux, demandent des droits admin (f14, b12, b13) : ticket à la DSI. Sur un home partagé, couper les mises à jour (b24, b25).
12. **Intégrité du binaire.** Vérifier la signature GPG du `manifest.json` avec l'empreinte publiée (b26).
13. **Mode hors ligne (air-gap).** Claude Code exige Internet (e15) ; Ollama : `OLLAMA_NO_CLOUD=1` et modèles téléchargés à l'avance (e2, e3) ; vLLM : documentation hors ligne via `--enable-offline-docs` (e6) ; OpenCode : petit modèle de titres hébergé par Zen par défaut, à rediriger (e9) ; Kilo Code : flux de données inconnus avec un endpoint perso (e12) ; aucun mode hors ligne décrit pour Copilot, Codex, Cursor ou Gemini (e16).
14. **Skills et instructions multi-outils.** Un skill placé dans `.claude/skills` est aussi lu par Copilot (a19) ; `CLAUDE.md` et `AGENTS.md` sont lus par Copilot (a21) ; le contrôle organisationnel des skills n'est pas décrit (a20) : à demander à l'éditeur.
15. **Ce qu'on ne promet pas sans confirmation.** Faits UNVERIFIED ou PRESS à ne pas citer comme acquis : a9, a16, a18, a20, a24, c5, c6, d5, d6, d9, d12, d14, d19, d20, e7, e12, e14, e16, f7, f9, f16.
