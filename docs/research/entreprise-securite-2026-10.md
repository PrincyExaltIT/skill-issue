# Sécurité, conformité et prévention : notes de recherche

## Méthode

Collecte réalisée le 10 octobre 2026. Point d'entrée : recherche web. Ensuite, lecture des pages primaires : ANSSI (cyber.gouv.fr et messervices.cyber.gouv.fr), CNIL (cnil.fr), EUR-Lex, AI Act Service Desk et page AI Office de la Commission, OWASP GenAI, documentation Claude Code et Anthropic, GitHub Docs, OpenAI, spécification MCP et agentskills.io. Les pages ont été lues avec un outil de résumé : les formulations sont donc des paraphrases, sauf les termes entre guillemets. Les PDF (guide ANSSI, NIST AI 600-1) n'ont pas été lisibles ; leur contenu est soit relayé par la presse (PRESS), soit non vérifié (UNVERIFIED). Statuts : VERIFIED = vu aujourd'hui sur une page officielle ; PRESS = presse, blog de sécurité ou blog de fournisseur, non confronté au texte officiel ; UNVERIFIED = non vérifié aujourd'hui (source partielle, document illisible ou point à confirmer). Les conflits de dates sont signalés dans le fait concerné. Ce document n'est pas un avis juridique : les points de droit sont à faire valider par le juriste du client.

## 2. CNIL

- **b20.** La CNIL publie la version finale de ses fiches sur le développement des systèmes d'IA le 22 juillet 2025. Source : https://www.cnil.fr/fr/ia-finalisation-recommandations-developpement-des-systemes-ia . Statut : VERIFIED.
- **b21.** Les recommandations sur l'intérêt légitime pour le développement de l'IA sont publiées le 19 juin 2025. Source : https://cnil.fr/fr/recommandations-developpement-ia-interet-legitime . Statut : VERIFIED.
- **b22.** L'intérêt légitime peut servir de base légale au développement d'un système d'IA, sous réserve de garanties fortes ; le consentement n'est pas systématiquement requis. Source : https://cnil.fr/fr/recommandations-developpement-ia-interet-legitime . Statut : VERIFIED.
- **b23.** Garanties citées par la CNIL : exclure certaines données de la collecte ; accroître la transparence ; faciliter l'exercice des droits ; informer les personnes ; prévoir un droit d'opposition discrétionnaire ; limiter le traitement à des données pseudonymisées ou anonymisées. Source : https://cnil.fr/fr/recommandations-developpement-ia-interet-legitime . Statut : VERIFIED.
- **b24.** Exemple donné par la CNIL : réutiliser les conversations futures des utilisateurs d'un agent conversationnel pour améliorer le modèle peut reposer sur l'intérêt légitime, avec les garanties ci-dessus. Source : https://cnil.fr/fr/recommandations-developpement-ia-interet-legitime . Statut : VERIFIED.
- **b25.** Un modèle entraîné sur des données personnelles relève souvent du RGPD, en raison de ses capacités de mémorisation. Source : https://www.cnil.fr/fr/ia-finalisation-recommandations-developpement-des-systemes-ia . Statut : VERIFIED.
- **b26.** La CNIL propose la mise en place de filtres robustes au niveau du système qui encapsule le modèle comme mesure de protection. Source : https://www.cnil.fr/fr/ia-finalisation-recommandations-developpement-des-systemes-ia . Statut : VERIFIED.
- **b27.** La fiche « Garantir la sécurité du développement d'un système d'IA » vise un développement dans un environnement sécurisé et détaille risques et mesures. Source : https://www.cnil.fr/fr/ia-finalisation-recommandations-developpement-des-systemes-ia . Statut : VERIFIED.
- **b28.** Le projet PANAME, mené avec l'ANSSI, iPoP et PEReN, doit évaluer si un modèle traite des données personnelles ; sa date n'est pas fixée. Source : https://www.cnil.fr/fr/ia-finalisation-recommandations-developpement-des-systemes-ia . Statut : VERIFIED.
- **b29.** Le sous-traitant traite des données pour le compte d'un responsable de traitement ; son contrat doit prévoir transparence et traçabilité, protection dès la conception et par défaut, sécurité des données, assistance, alerte et conseil. Source : https://www.cnil.fr/fr/definition/sous-traitant . Statut : VERIFIED.
- **b30.** La fiche CNIL sur le sous-traitant ne cite pas l'article 28 du RGPD et ne détaille ni les instructions documentées ni la sous-traitance ultérieure. Source : https://www.cnil.fr/fr/definition/sous-traitant . Statut : VERIFIED.

## 3. Règlement européen sur l'IA (AI Act)

- **b33.** Règlement (UE) 2024/1689 (AI Act), texte officiel consulté en version française. Source : https://eur-lex.europa.eu/eli/reg/2024/1689/oj/fra . Statut : VERIFIED.
- **b34.** Article 4, version d'origine : fournisseurs et déployeurs doivent prendre des mesures pour assurer « un niveau suffisant de maîtrise de l'IA » à leur personnel et aux autres personnes qui font fonctionner ou utilisent les systèmes pour leur compte. Source : https://eur-lex.europa.eu/eli/reg/2024/1689/oj/fra . Statut : VERIFIED.
- **b35.** L'article 4 est applicable depuis le 2 février 2025 (chapitres I et II, article 113). Source : https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-113 et https://digital-strategy.ec.europa.eu/en/faqs/ai-literacy-questions-answers . Statut : VERIFIED.
- **b36.** Selon l'article 113, le chapitre V (modèles d'IA à usage général) et d'autres dispositions s'appliquent depuis le 2 août 2025. Source : https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-113 . Statut : VERIFIED.
- **b37.** Application générale de l'AI Act à partir du 2 août 2026, sous réserve des exceptions de l'article 113. Source : https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-113 . Statut : VERIFIED.
- **b38.** Le déployeur (article 3, point 4) est toute personne ou entité qui utilise un système d'IA sous sa propre autorité, hors usage personnel non professionnel. Source : https://eur-lex.europa.eu/eli/reg/2024/1689/oj/fra . Statut : VERIFIED.
- **b39.** Le devoir de maîtrise de l'IA vise aussi les personnes qui font fonctionner ou utilisent les systèmes pour le compte du fournisseur ou du déployeur (prestataires, sous-traitants). Source : https://digital-strategy.ec.europa.eu/en/faqs/ai-literacy-questions-answers . Statut : VERIFIED.
- **b40.** La FAQ de la Commission indique qu'aucun certificat n'est requis, qu'aucune formation obligatoire n'est imposée et que l'article 4 n'impose pas de mesurer les connaissances des salariés. Source : https://digital-strategy.ec.europa.eu/en/faqs/ai-literacy-questions-answers . Statut : VERIFIED.
- **b41.** La FAQ de la Commission juge souvent insuffisant de se fier seulement à la notice d'utilisation. Source : https://digital-strategy.ec.europa.eu/en/faqs/ai-literacy-questions-answers . Statut : VERIFIED.
- **b42.** Le règlement (UE) 2026/1744, dit « Digital Omnibus on AI », est adopté le 8 juillet 2026 et publié au Journal officiel le 24 juillet 2026 ; il entre en vigueur le troisième jour suivant la publication, soit le 27 juillet 2026 (calcul à partir de la règle du texte). Source : https://eur-lex.europa.eu/eli/reg/2026/1744/oj . Statut : VERIFIED.
- **b43.** Le nouvel article 4 demande aux fournisseurs et déployeurs de « prendre des mesures » pour favoriser la maîtrise de l'IA ; aucun niveau précis n'est imposé à chaque personne ; la Commission publiera des exemples pratiques. Source : https://eur-lex.europa.eu/eli/reg/2026/1744/oj . Statut : VERIFIED.
- **b44.** Article 26 (déployeurs de systèmes à haut risque) : usage conforme aux notices, contrôle humain confié à des personnes compétentes, pertinence des données d'entrée, surveillance, signalement des incidents graves. Source : https://eur-lex.europa.eu/eli/reg/2024/1689/oj/fra . Statut : VERIFIED.
- **b45.** Article 26, paragraphes 6 et 7 : journaux conservés au moins six mois ; information des représentants et des travailleurs avant la mise en service sur le lieu de travail. Source : https://eur-lex.europa.eu/eli/reg/2024/1689/oj/fra . Statut : VERIFIED.
- **b46.** Un assistant de code généraliste n'est pas à haut risque par défaut ; la qualification dépend de l'usage prévu (annexe III). Source : https://eur-lex.europa.eu/eli/reg/2024/1689/oj/fra . Statut : UNVERIFIED (annexe III non relue aujourd'hui).
- **b47.** Article 50 (« Transparency obligations for providers and deployers of certain AI systems ») : les personnes doivent être informées qu'elles interagissent avec un système d'IA. Source : https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-50 . Statut : VERIFIED.
- **b48.** Article 99, paragraphe 3 : amendes jusqu'à 35 M€ ou 7 % du chiffre d'affaires mondial annuel (le plus élevé des deux) pour les pratiques interdites de l'article 5. Source : https://ai-act-service-desk.ec.europa.eu/en/ai-act/article-99 . Statut : VERIFIED.
- **b49.** Article 99, paragraphe 4 : amendes jusqu'à 15 M€ ou 3 % du chiffre d'affaires pour les autres obligations, dont celles des articles 26 et 50 ; l'article 4 n'y figure pas (déduction du texte consulté). - **b50.** Les systèmes à haut risque de l'annexe III (article 6, paragraphe 2) sont reportés au 2 décembre 2027. Source : https://eur-lex.europa.eu/eli/reg/2026/1744/oj . Statut : VERIFIED.
- **b51.** Les systèmes à haut risque de l'annexe I (article 6, paragraphe 1) sont reportés au 2 août 2028. Source : https://eur-lex.europa.eu/eli/reg/2026/1744/oj . Statut : VERIFIED.

- **b53.** La presse indique que l'article 50 n'est pas concerné par le report du chapitre III ; il s'applique donc à partir du 2 août 2026. Source : https://www.iubenda.com/en/blog/ai-omnibus-adopted-august-2-obligations-july-2026/ . Statut : PRESS.

## 4. Risques propres aux agents (injection, skills, MCP, supply chain)

- **b55.** OWASP Top 10 pour les applications LLM 2025 : LLM01 Prompt Injection, LLM02 Sensitive Information Disclosure, LLM03 Supply Chain, LLM04 Data and Model Poisoning, LLM05 Improper Output Handling, LLM06 Excessive Agency, LLM07 System Prompt Leakage, LLM08 Vector and Embedding Weaknesses, LLM09 Misinformation, LLM10 Unbounded Consumption. Source : https://genai.owasp.org/llm-top-10/ . Statut : VERIFIED.
- **b56.** Le Top 10 OWASP pour les applications agentiques 2026 est publié le 9 décembre 2025 par le projet GenAI Security Project ; le contenu du site est sous licence CC BY-SA 4.0. Source : https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026 . Statut : VERIFIED.
- **b57.** Titres des entrées ASI01 à ASI10 : Agent Goal Hijack ; Tool Misuse & Exploitation ; Identity & Privilege Abuse ; Agentic Supply Chain Vulnerabilities ; Unexpected Code Execution ; Memory & Context Poisoning ; Insecure Inter-Agent Communication ; Cascading Failures ; Human-Agent Trust Exploitation ; Rogue Agents. Source : https://cycode.com/blog/owasp-top-10-agentic-applications/ . Statut : PRESS (les titres ne figurent pas sur la page OWASP consultée ; à confirmer dans le document officiel).
- **b58.** Claude Code en mode manuel demande avant les modifications et les commandes non lectures seules ; en mode auto, un classifieur examine les actions et bloque celles jugées dangereuses ; les règles de refus explicites restent appliquées. Source : https://code.claude.com/docs/en/security . Statut : VERIFIED.
- **b59.** Le bac à sable de Claude Code isole le système de fichiers et le réseau au niveau du système d'exploitation ; la frontière du répertoire de travail n'est qu'une demande de permission, une commande Bash approuvée pouvant écrire partout où le compte peut écrire. Source : https://code.claude.com/docs/en/security . Statut : VERIFIED.
- **b60.** Dans Claude Code, curl et wget ne sont pas approuvés automatiquement ; une règle de refus ne vise que la commande telle qu'écrite, l'isolation réseau du bac à sable ne dépendant pas du texte de la commande. Source : https://code.claude.com/docs/en/security . Statut : VERIFIED.
- **b61.** Anthropic indique qu'aucun système n'est totalement à l'abri ; elle recommande de relire les commandes, d'éviter de transmettre directement du contenu non fiable à Claude et d'utiliser des machines virtuelles pour les services web externes. Source : https://code.claude.com/docs/en/security . Statut : VERIFIED.
- **b62.** Recherche Anthropic du 24 novembre 2025 : un taux de succès d'attaque de 1 % reste un risque significatif ; aucun agent navigateur n'est immunisé contre l'injection de prompt. Source : https://www.anthropic.com/research/prompt-injection-defenses . Statut : VERIFIED.
- **b63.** Spécification MCP (version de travail) : un serveur MCP local exécute des commandes avec les privilèges du client ; une installation en un clic doit afficher la commande exacte et exiger un consentement explicite. Source : https://modelcontextprotocol.io/specification/draft/basic/security_best_practices . Statut : VERIFIED.
- **b64.** Spécification MCP : un serveur ne doit jamais accepter des jetons qui ne lui ont pas été émis explicitement (interdiction du token passthrough). Source : https://modelcontextprotocol.io/specification/draft/basic/security_best_practices . Statut : VERIFIED.
- **b65.** Spécification MCP : un proxy doit implémenter un consentement par client, sans quoi il est exposé au problème du confused deputy. Source : https://modelcontextprotocol.io/specification/draft/basic/security_best_practices . Statut : VERIFIED.
- **b66.** Spécification MCP : limiter les scopes au strict nécessaire ; l'usage de scopes « omnibus » (*, all, full-access) est signalé comme erreur courante. Source : https://modelcontextprotocol.io/specification/draft/basic/security_best_practices . Statut : VERIFIED.
- **b67.** Spécification MCP : les clients devraient bloquer les plages IP privées et de lien local, dont les points de métadonnées cloud (169.254.0.0/16). Source : https://modelcontextprotocol.io/specification/draft/basic/security_best_practices . Statut : VERIFIED.
- **b68.** Claude Code : relire le fichier .mcp.json ne suffit pas, car des serveurs peuvent venir d'autres portées ou de plugins ; une configuration MCP managée permet de restreindre les serveurs autorisés. Source : https://code.claude.com/docs/en/security . Statut : VERIFIED.
- **b69.** Spécification Agent Skills : une skill est un dossier contenant SKILL.md et, en option, scripts/, references/ et assets/ ; le champ allowed-tools est expérimental. Source : https://agentskills.io/specification . Statut : VERIFIED.
- **b70.** La spécification Agent Skills ne contient pas de section sécurité (ni épinglage de dépendances, ni vérification d'intégrité, ni déclaration de capacités). Source : https://agentskills.io/specification . Statut : VERIFIED (constat d'absence sur la page consultée).
- **b71.** Claude Code : une skill peut embarquer et exécuter des scripts dans n'importe quel langage ; allowed-tools pré-approuve des outils pour le tour d'invocation sans restreindre les autres, et les règles de refus restent prioritaires. Source : https://code.claude.com/docs/en/skills . Statut : VERIFIED.
- **b72.** Claude Code : la confiance de l'espace de travail ne contrôle pas allowed-tools ; il faut relire les allowed-tools des skills versionnées dans un dépôt avant de lancer Claude Code dessus. Source : https://code.claude.com/docs/en/skills . Statut : VERIFIED.
- **b73.** Claude Code : des réglages d'administration permettent de désactiver l'exécution de commandes shell par les skills (disableSkillShellExecution), d'ignorer les allowed-tools des skills de projet (allowManagedPermissionRulesOnly) et de refuser des skills précises par règle. Source : https://code.claude.com/docs/en/skills . Statut : VERIFIED.
- **b74.** Une étude académique (arXiv 2601.10338) rapporterait que plus d'un quart des skills publiques contiennent au moins une vulnérabilité ; chiffre relayé par un article de Mondoo non vérifié sur le PDF. Source : https://arxiv.org/pdf/2601.10338 . Statut : UNVERIFIED.
- **b75.** Juillet 2025 : une commande destructrice injectée dans une version publiée de l'extension VS Code Amazon Q Developer ; AWS a publié une version corrigée. Source : https://bleepingcomputer.com/news/security/amazon-ai-coding-agent-hacked-to-inject-data-wiping-commands . Statut : PRESS.
- **b76.** Août 2025, campagne « s1ngularity » : versions npm malveillantes du paquet Nx avec script post-install volant tokens et clés SSH ; accès initial par injection de code via le titre d'une PR dans un workflow GitHub Actions utilisant pull_request_target. Source : https://www.wiz.io/blog/s1ngularity-supply-chain-attack . Statut : PRESS (blog de fournisseur).
- **b77.** La même campagne a lancé des CLI d'IA (Claude, Gemini, Q) avec des options de contournement des permissions (--dangerously-skip-permissions, --yolo, --trust-all-tools) et exfiltré les données vers des dépôts publics nommés s1ngularity-repository. Source : https://www.wiz.io/blog/s1ngularity-supply-chain-attack . Statut : PRESS.
- **b78.** GitHub Actions : éviter pull_request_target si ce n'est pas nécessaire ; ne jamais extraire du code non fiable (dont celui des forks) dans ces workflows ; donner au GITHUB_TOKEN les permissions minimales, en lecture seule par défaut. Source : https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions . Statut : VERIFIED.
- **b79.** GitHub Actions : épingler une action sur un SHA de commit complet est le seul moyen de l'utiliser comme version immuable ; un tag peut être déplacé ou supprimé. Source : https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions . Statut : VERIFIED.
- **b80.** Copilot coding agent ne modifie que le dépôt de la tâche, une branche à la fois, une PR par tâche, avec une durée maximale de 59 minutes ; GitHub recommande de relire et tester la sortie avant production. Source : https://docs.github.com/en/copilot/concepts/coding-agent/about-copilot-coding-agent . Statut : VERIFIED.
- **b81.** Démonstration publique (Trail of Bits, 6 août 2025) : des instructions cachées dans une issue, placées dans une balise image car les commentaires HTML sont retirés, conduisent Copilot à produire une PR avec une porte dérobée. Source : https://blog.trailofbits.com/2025/08/06/prompt-injection-engineering-for-attackers-exploiting-github-copilot/ . Statut : PRESS.
